# First deploy of voodu-webui onto runa — the order that works

The manifest is `voodu.hcl`. Everything below is what it deliberately does not
contain.

## 0. Build mode — what ships is the working tree

The manifest builds on the box from a tarball of this checkout. No tag, no CI
wait. Two things follow:

- Commit first anyway. A build from an uncommitted tree is a build nobody can
  reproduce, and `vd rollback` only takes you back to the previous BUILD, not to
  a commit.
- `.dockerignore` is the boundary: it already excludes `*.private.pem`,
  `config/master.key`, `storage/`, `node_modules/`. Anything new that is secret
  goes there before the first `apply`.

The ghcr image (release.yml on v* tags) is for self-hosted customers only.

## 1. Postgres (the one runa already has)

The primary moves to Postgres when DATABASE_URL is set. Create a database and a
role for the console on the existing instance, then:

    vd -r runa config runa/webui set DATABASE_URL="postgres://webui:<pass>@<pg-host>:5432/voodu_webui"

`<pg-host>` is the pod's DNS name on the box (`pg-0.<scope>` for a plugin
postgres). The image runs `db:prepare` on boot, so no manual migration.

## 2. Sign-in (SaaS)

    vd -r runa config runa/webui set CLOWK_PUBLISHABLE_KEY=pk_live_… CLOWK_SECRET_KEY=sk_live_…

`CLOWK_ENABLED=1` is in the manifest; the app refuses to boot with it on and no
publishable key, which is the intended failure.

## 3. Poller + licence + base URL

    vd -r runa config runa/webui set POLLER_TOKEN="$(openssl rand -hex 32)"
    vd -r runa config runa/webui set APP_BASE_URL="https://console.voodu.clowk.in"

The unlimited tier is a licence, minted locally with the signing key:

    bundle exec rake 'license:issue[voodu-hosted,365,tier=unlimited]' > /tmp/hosted.jwt
    vd -r runa config runa/webui set VOODU_LICENSE="$(cat /tmp/hosted.jwt)"

Without it the console boots as the free tier and the Deploys tab does not
exist (Entitlements#deploy_plane?).

## 4. Registry, DNS, apply

- An A record for console.voodu.clowk.in → the box, ports 80/443 open, caddy
  plugin installed (it is what `ingress` expands into).

    vd -r runa remote add runa voodu@v2202608404827506728.megasrv.de   # once
    vd -r runa diff  -f voodu.hcl
    vd -r runa apply -f voodu.hcl
    vd -r runa logs  runa/webui -f

The first apply builds three stages (Go poller, bundle install, esbuild +
tailwind + assets:precompile) — expect several minutes on a VPS. Later applies
hit the layer cache and are much shorter.

## 5. After the first boot

- Register runa itself as a Server in the console (endpoint + a PAT with the
  deploy scope) — the console does not know the box it runs on.
- Configure the GitHub App (Ops::GithubConfig) in the console UI, then point the
  App's webhook URL at https://console.voodu.clowk.in/integrations/github/webhook
  with the same secret.
- Back up: the Postgres database AND the `voodu-webui-storage` volume, together.
  The encryption keys for the PATs live in the volume; the ciphertext in Postgres.
